Visual direction: “docked studio, after OpenFilm” and what changed from the first pass

The editor is a set of calm, docked panes on a slightly darker board. Narrow seams and small corners separate them instead of heavy borders. Layers sit on the left, the canvas in the middle, the inspector on the right, and a real timeline runs across the bottom. This follows OpenFilm’s studio. All colours come from the host theme, so the board, panes and the canvas surround follow light or dark. Only the video template keeps its own fixed colours, because they are content. Colour still means something: primary marks spreadsheet data and the main action, the ring marks selection and the playhead, and status colours mark done, warning, blocked and in progress.

Chosen: docked studio (OpenFilm)

A real editor layout, kept calm: theme panes, seams, a restrained header. Spreadsheet, connection and batch screens reuse the same panes. Our additions: data pills, the row-driven countdown clip, review and retry screens.

Superseded: workbench with a constant dark stage

Our first pass put the video on a dotted dark stage in every theme, with scene cards and a short strip of segments. It did not feel like an editor, and the dark block fought the light theme. Kept: theme-following chrome, meaning-only colour, monospace column names.

Not chosen: playful, Canva-like

Good for browsing templates, but brand gradients compete with the user’s video colours and airy flyouts are too sparse for 100-row review. Kept: starting from a template, plain-language labels.

We no longer reject the pro-editor arrangement. We still avoid forcing an all-dark, dense grey-on-black look in a light theme, and we keep tracks fixed to four scenes rather than freeform multi-track editing.

Evidence, verification and limits
  • SOURCE: OpenFilm (OF) files pinned to commit b7673b5: README, LICENSE (MIT), globals.css, ProjectView.tsx, layer, inspector, viewer, timeline and export components, plus frames from the public README demo. We read them; we did not run or sign into OpenFilm. Our CSS and JS are original and copy no OpenFilm code.
  • DOC: Canva help (C1, C3) and Creatomate (K2) were read earlier as reader snapshots. Canva help returns HTTP 403 to direct requests. Figma (R1, R2), Airtable (R3) and GitHub (R4) were read for this page. These are documents, not sessions.
  • OBS: the synthetic demo adapts research/fixtures and adds validation cases: repeated sample riddles, a Hindi row, an Arabic (right-to-left) row, an overlong question, an empty question, and an invalid answer letter plus negative countdown.
  • Not observed: Canva’s signed-in Bulk Create for video, its multi-scene behaviour, or its real export. REA was not run because its compiled runtime is missing.
  • PROPOSED: how the OpenFilm layout is adapted (tree, inspector sections, layer and audio lanes, the hatched per-row countdown clip), every screen, the default timing (4 s question + per-row countdown + 4 s reveal + 2 s outro), the 62 px minimum text size, the fit threshold and the file naming.
  • Simulated here: rendering, the two failures and the retry, the test export, ZIP contents and per-file downloads. Only manifest.csv is a real file.
